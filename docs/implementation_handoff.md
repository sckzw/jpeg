## 現在地と依頼内容

JPEG_TOPのRTL、参照モデル、単体・結合・A4性能試験を実装済み。現在の結果は[implementation_status.md](implementation_status.md)、実装上の具体化は[rtl_interfaces.md](rtl_interfaces.md)を参照する。チャット履歴を前提にせず、本書と実装状況から継続する。

## 読む順序と仕様の優先順位

1. [requirements.md](requirements.md)：ユーザーが決めた目的・性能・I/F・画像寸法。行に「設計案」とある部分は提案。
2. [blocks/rtl_contract.md](blocks/rtl_contract.md)：初回実装のポート、レジスタ、テーブル、演算、停止契約。
3. [design_spec.md](design_spec.md)：全体のCPU／RTL分担、DRAM形式、接続・性能見積り。
4. [blocks/README.md](blocks/README.md)と各ブロック仕様：接続図と個別動作。

ユーザー確定要件を最優先。旧仕様の「未決」「初期案」や同じ項目の競合にはrtl_contractの具体的な実装値を使用する。特に量子化は2台の反復除算器ではなく32段パイプライン除算、係数幅は32bit、APB追加レジスタは固定配置にする。設計案はユーザーが個別に確定した要件と同一視しない。

誤り・矛盾を発見したら、根拠と修正をMarkdownに記録してから実装する。ポート名などの低影響な詳細は既定規則に従い具体化してよい。性能・対応範囲を変える場合は明示する。全仕様を再提案して作業を止める必要はない。

## 維持するユーザー確定事項

- Verilogによるエンコーダーとデコーダー。両モードは排他、資源共有。
- YCbCr各8bit、Baseline Sequential DCT・Huffman。Progressive／Lossless対象外。
- 最大幅65535画素、最大高さ65535画素。
- APBによるCPU設定。HuffmanテーブルもCPUがロードする。
- 内蔵DMA、AXI4、リードはjpeg_dma_read、ライトはjpeg_dma_writeの別モジュール。
- 256 MHz。A4・300 dpi、2480×3508画素の模擬原稿で100 ppm。
- AXI読出しデータ返却平均500 ns、書込み応答平均500 ns。
- 圧縮できない場合の性能見積りは圧縮率1:1。
- 模擬原稿はHP／Brotherのサムネイルを参考に検証時に作成する。公開原稿そのものの入手は前提としない。

## 初回RTLの設計選択

- DRAMはYCbCr planarラスタ配置、成分別base／stride。ラインバッファなし、8×8ブロック単位。
- AXI64bit、画像1 beat／行を8行へ別要求。JPEGは最大16 beats。read/write各8 outstanding。同一ID初期案。
- 入出力JPEG FIFOは各2,048 byte、画素RAMと各段の係数RAMは各2面。
- ADDR_W初期64、ID_W初期1、COEF_W=32。APBは12bitアドレス／32bitデータ。
- 4:4:4／4:2:2／4:2:0、単一scan、Y→Cb→Cr、encodeはRestartなし。decodeは2026-10-06のユーザー依頼でDRI/RST対応（[拡張契約](restart_decode.md)）。
- CPUがヘッダ・色変換・サブサンプリング・テーブル準備を担当。RTLは圧縮scanデータを入出力する。
- 整数演算定数と丸め、テーブル格納、停止後のAXI回収はrtl_contractに従う。

これらに基づいて実装・性能測定済み。段間2面RAMによる重畳、変換入力2面化、JPEG書込み最大16 beatsによりサイクル予算を満たした。数値と測定条件は実装状況を参照する。

## 作成する構成と手順

| ディレクトリ・ファイル | 内容 |
|---|---|
| rtl/jpeg_*.v | 合成可能Verilog-2001。各仕様書のモジュール名と一致 |
| rtl/jpeg_defs.vh | 共通幅・レジスタ・エラー定数。仕様値を重複させない |
| sim/ | Verilatorテストベンチ、APBドライバ、AXIメモリモデル |
| tools/ | 固定小数点参照モデル、テーブル生成、画像・JPEG変換 |
| tests/data/ | 生成画像・小さなベクトルと生成条件 |
| Makefile | lint、単体、結合、性能試験の入口 |
| docs/implementation_status.md | 実装済み／未実装、コマンド、結果、残課題 |

既存環境のVerilator・C++コンパイラ・Python・JPEGライブラリの有無とバージョンを先に確認する。存在やネットワークアクセスを推測しない。不足時は可能な実装と検証を進め、外部相互運用など未実行の試験を明記する。

1. rtl_contractから定数・ポート一覧を確定して記録し、参照モデルとテーブル生成を用意する。
2. FIFO／RAM、APB／ctrl、read／write DMAを実装・単体検証する。
3. transform／quantを整数モデルに一致させ、entropy／bitstreamを符号ベクトルで検証する。
4. jpeg_topを結合し、CPUの設定・ヘッダ操作をテスト側で模擬する。
5. 小画像の外部JPEG相互運用、停止・エラー・端数・連続ジョブを検証する。
6. 模擬A4画像を生成し、性能を測定してボトルネックを修正する。

仮のstubで接続した場合は未実装として記録する。実体のないdone、固定出力、ソフトウェアへの処理委譲でRTL完了を装わない。ソフトウェアは参照・CPU担当範囲だけに用いる。

## 検証と残課題の扱い

- モジュール動作・符号処理・整数演算モデルとの一致は初回の合格条件。
- Verilatorのlintと単体・結合試験を再現可能なコマンドにする。乱数seedと入力条件を記録。
- AXI平均500 nsは128 cycle。最初は固定128 cycleの応答モデル、その後はseed固定の遅延変動とread/write競合を追加する。128cycleは先頭R／最終W後のBまでの遅延としてモデル化し、AR/AW/Wの受付待ちは別に計測する。
- 4:4:4は408,270ブロック／ページ、全体予算153,600,000 cycle／ページ。RTLの測定だけでCPU込み100 ppm達成としない。CPU時間の予算を別に記録する。
- 256 MHzのサイクル換算と実デバイスでの256 MHz成立は区別する。対象デバイスは未指定で、合成・配置配線の保証は対象外。
- 固定小数点モデルとのbit一致を先に確立する。外部実装との画素差・PSNRは測定し、最終的な画質しきい値は評価を報告して決める。
- 原稿サムネイルはHP本文・リンク確認済みだが画像自体は未取得。Brotherは403。再取得できなければ文字・表・グラフ・写真風の模擬画像を生成し、実際のサムネイルを確認できなかったことを明記する。
- 圧縮率1:1を出力容量の絶対上限にしない。入力以上に膨張するJPEGと容量超過も試験する。

最終報告には実装範囲、実行コマンド、合否、サイクル数、未検証項目を含める。次のセッションにも実装状況文書から継続できる状態にする。
