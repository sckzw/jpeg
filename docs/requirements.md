# JPEGエンコーダー・デコーダー RTL 要件定義

プロジェクト名：JPEG_TOP  
作成者：shuichi  
更新日：2026-10-05

未決事項は `TBD` とする。詳細な回路仕様は設計時に定義する。

## 1. 目的・構成

- 目的：AIによるVerilog（RTL）設計の実証
- 成果物：JPEGエンコーダー・デコーダーのVerilog RTL
- 対象デバイス：指定なし（Verilogコーディングまで）
- 動作：エンコードとデコードは同時動作せず、資源を共有する
- 処理分担：高速化が必要な処理はRTL、それ以外はCPU（Arm）で処理する。具体的な分担はTBD

## 2. JPEG対応範囲

| 項目 | 内容 |
|---|---|
| 方式 | Baseline Sequential DCT、Huffman符号化 |
| 色空間・精度 | YCbCr、各成分8bit |
| サンプリング比 | JPEG規格準拠（具体的な対応範囲はTBD） |
| Huffmanテーブル設定 | エンコーダー・デコーダーともCPUからAPB経由で設定 |
| Huffmanテーブル最適化 | CPU側での実施有無はTBD |
| 量子化テーブル・画質設定 | TBD |
| JPEGヘッダの処理担当 | TBD（RTL／CPU） |
| その他の対応範囲 | TBD（Restartなど） |
| 対象外 | Progressive、Lossless |

## 3. 入出力

| 項目 | 内容 |
|---|---|
| 画像の最大幅 | 65535画素 |
| 画像の最大高さ | 65535画素 |
| 入出力方式 | AXIリード・ライトを別ブロックとする内蔵DMAで画像・JPEGデータを転送 |
| DMAの外部I/F | AXI4マスター |
| AXI4リード初期仕様 | 64bit、画像1 beat／JPEG最大16 beats、最大8要求アウトスタンディング |
| AXI4ライト初期仕様 | 64bit、復号画像1 beat／圧縮データ最大16 beats、最大8要求アウトスタンディング |
| AXI4応答時間の評価条件 | リード返却まで平均500 ns、ライト応答まで平均500 ns |
| 画素形式・並び順 | 設計案：8bit YCbCr planar、成分ごとのラスタ順。DMAが内部MCU順へ変換 |
| JPEGデータの転送方式 | 設計案：DRAM上の連続バイト列を内蔵DMAで転送 |
| CPUからの設定・制御 | APB |
| 端数サイズの扱い | 設計案：RTLで端画素を複製。復号時は有効領域だけを書込み |

## 5. 開発・完了条件

- Verilogの版・シミュレータ：Verilator
- 参照ソフトウェア：TBD
- テスト画像：検証時に、[Brotherの印刷速度説明ページ](https://support.brother.com/g/s/id/printspeed/index.html)のサムネイルを参考に模擬画像を作成する。ISO/IEC 24734・24735の正式な原稿の代替としてプロジェクト内の評価に使用する。
- 追加の参照先：[HPのISO/IEC 24734説明ページ](https://www.hp.com/products1/ISO/MMDPP/index.html)。本文とAdobe Reader・Word・Excelのテスト原稿のサムネイルへの参照は確認済み。画像ファイルは取得できておらず、画像自体は未確認。検証時に取得・確認して模擬画像の作成に使用する。
- 模擬画像の用紙サイズ・解像度：A4（210 × 297 mm）・300 dpi。各辺を最も近い整数に丸め、2480 × 3508画素とする。
- 模擬画像の色形式・画質設定：TBD
- エンコード結果を外部のJPEGソフトウェアで復号できる
- 外部で生成したJPEGをデコードできる
- 指定した性能目標を達成
